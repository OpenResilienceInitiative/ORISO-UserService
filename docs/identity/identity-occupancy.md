# Exact identity occupancy

`POST /service/useradmin/identity-observations` is a read-only collision check. The service context path is `/service`; the generated operation is `/useradmin/identity-observations`. Only a nontechnical platform administrator with `USER_ADMIN` can reach the lookup. Tenant zero alone grants no access.

The response scope is always `identity-occupancy-v1`. ID, username and email selectors form a union across the configured Keycloak realm and raw admin, consultant and asker rows. Disabled provider identities and soft-deleted relational rows still occupy an identity. Admin has no deletion column, so its deletion state is unknown. No agency or role-grant inventory is implied.

Underscores are literal selector characters, including canonical `_at_` usernames. Selectors never become query patterns; `%`, `*`, `?` and control characters are rejected.

A complete observation with one matching identity returns `200` / `OCCUPIED`. A complete, empty observation returns `200` / `FREE`; clients must inspect both the completeness flag and occupancy, because HTTP 200 alone does not mean free. Multiple matching identity IDs conflict (`409`). Reaching a bound also returns `409` with an incomplete observation. A failed dependency returns `502`; already observed positive facts are retained. Raw provider and database failure details are not exposed. Invalid selectors return a fixed explanatory 400; unexpected post-parsing service/mapping errors return a sanitized empty 500. Failure diagnostics contain only fixed source/type information, never selector or raw exception text. Every response from the observation adapter uses `Cache-Control: no-store`.

Fixed bounds are 20 distinct identities and 21 projected rows per relational exact query. Exact provider selector queries use pages of 100 for at most 20 pages. Relational encoded candidates use primary-key keyset continuation with 100 rows per page and at most 20 pages; a full final page is incomplete. The first page has no artificial cursor minimum, and later pages bind the last observed native key, so deleting an earlier row cannot shift a persistent collision past an offset. The provider encoded-candidate scan uses one fixed `enc.` search with `first=0` / `max=2000`; fewer than 2000 valid results may complete, while a full 2000 response is incomplete and an oversized/invalid response fails closed. This avoids an inter-request provider candidate offset gap. Candidate population is separate from the 20 matching-identity bound.

A username probe cannot return `FREE` when any source reaches the 2,000-candidate bound without proving exhaustion, or when an inspected encoded username cannot be resolved. `FREE` requires every queried layer to complete. These limits return an incomplete `409` (`UNKNOWN` when no positive fact was found); dependency failures return `502`. Callers must not treat `409` or `UNKNOWN` as vacancy. This bound applies to each source's encoded candidates for username probes, not the deployment's total user population.

Username comparison decodes the existing `enc.` Base32 representation before comparing without case sensitivity. Exact raw/encoded lookups are supplemented by the bounded encoded-candidate scans. Malformed encodings make the layer incomplete. Only exact decoded matches enter the response. Relational queries use fixed identifiers and bound parameters, with no active/deleted filter or ORM association loading. They do not change the caller's tenant context.

The single provider response can materialize up to 2000 user representations at once, compared with 100 per previous candidate page; record counts do not impose a fixed byte limit. The pinned Keycloak 26.0.4 client/server API accepts an explicit max, but actual deployed/custom-storage handling of 2000 still requires environment acceptance. This endpoint does not provide an atomic cross-source snapshot.

This endpoint creates or changes nothing. Observation is not an ownership receipt, a creation reservation, a complete resource inventory, proof of physical absence, or permission to release a fixture lease. Matrix, sessions, agencies, grants, creation races and lifecycle recovery require their own authoritative checks.
